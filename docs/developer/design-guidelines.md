# Wish UI design guidelines

This is a working baseline for contributors. It describes the frontend on 20 November 2026, including changes since release 0.2.9. Visual defaults are open to revision. The history below records which user problems prompted earlier changes, so a redesign can solve those problems in another way. Use the style preview to reproduce current behavior. Product feedback takes precedence when revising these examples.

Recent product requests specifically called for a desktop lower-right notification stack and mobile top banners, quiet routine compaction, a notification when a working session becomes idle, and an ordinary bin for an available delete action. Card width, spacing, icon weight and timing below are implementation choices that can be tuned independently.

## Choose the surface from the task

| User task | Starting component | Design consideration |
| --- | --- | --- |
| Read a conversation while inspecting another object | Session workspace and `IslandSidebar` | Dock the inspector when both panes have room. A narrow workspace uses a drawer. Closing it returns the reader to their place. |
| Browse several groups of settings or statistics | `OverlayWindow` and the relevant feature page | On desktop, open a window over the originating page. On mobile, give the destination a page with a Back control. Preserve the conversation or draft underneath. |
| Name an object, edit a short form or confirm a deletion | `Modal compact` | Put the title in the content flow, keep related fields together and end with the verb for the action. Name any linked objects affected by deletion. |
| Inspect a long tool result, file or diagnostic record | Detail pane, secondary page or mobile content sheet | Give the body a scroll owner. Keep the title and return action reachable. Contain wide code, tables and diffs inside their own horizontal viewport. |
| Act on the current object | `Menu` and `Hint` | Anchor actions close to their trigger and allow for viewport collisions. A hint can explain an icon. A touch user needs an actual way to invoke the action. |
| Choose a value or switch views | `SelectField`, `SegmentedControl` or a domain picker | Keep a few peer views visible as segments. For a long catalog, expose search, the current value and a selection mark. Provider and model pickers preserve the catalog hierarchy. |
| Learn that something happened elsewhere | `ToastHost` and `ToastCard` | Use a corner notification for a short result or an update offer. Keep field validation beside the field. Use the error dialog when someone needs the cause or recovery details. |

Generic controls belong in `src/ui`. Shared presentation that understands sessions, media, accounts or configuration belongs in `src/domain`. Feature pages compose these parts. Vendor extensions can reuse the tool-result and media views. When two entry points expose the same operation, check them together. For example, the account list and account editor both choose the delete icon from the button's availability. [Shared components](../../src/ui/components/) · [Module boundaries](architecture.md)

### Size short dialogs around their content

A preview with a selector and a play action needs room for those two controls, a short title and Close. Start with `Modal compact`. Put the title and Close on one unruled line, align the selector and action on the next, and let the longest translated choice determine the comfortable width. Keep a viewport margin, allow controls to wrap under text enlargement, and preserve usable hit targets. Reserve a separate action bar for a task with a distinct final decision. A lone display preference belongs beside the title when it affects the sample. The notification sample plays at the viewport edge, so its window only needs the playback controls. A code or transcript sample needs a reading column and can offer a width toggle. [Style preview](../../src/features/debug/StylePreview.vue)

### Use themed selection menus

For application choices, use `SelectField` or the relevant Wish picker. Style the full interaction, including the list opened from the trigger. Its floating surface, focused and hovered options, current-value checkmark, text and borders use the popup palette. A styled HTML select still hands its open menu to the browser on some platforms. Open the list during review in both themes, choose an option with the keyboard, and check Escape, focus return and touch selection. [Select field](../../src/ui/components/SelectField.vue)

## Visual hierarchy and theme roles

| Role | Tokens | Where it applies |
| --- | --- | --- |
| Canvas, raised item, floating surface | `--bg`, `--bg-raised`, `--bg-overlay` | Use the canvas for pages and scrimmed windows, a raised surface for their cards, and the floating surface for menus. |
| Control, recess, mobile group | `--bg-control`, `--bg-sunken`, `--bg-group` | Inputs, inset areas and grouped mobile rows each have a distinct surface. Hover, active and selected states need to remain legible on each. |
| Text hierarchy | `--fg`, `--fg-muted`, `--fg-subtle`, `--fg-faint` | Give names, results and values first reading priority. Supporting text, paths and times can recede. Read essential instructions against both themes. |
| Edge and focus | `--line`, `--line-strong`, `--focus-ring` | Use a quiet separator between adjacent panes. Bordered controls change their existing edge on keyboard focus. Other keyboard targets retain a visible focus indicator. |
| Accent, outcome, danger | `--accent`, `--accent-soft`, `--ok`, `--warn`, `--err`, `--danger` | Pair selection color with an indicator or outline. Give an error a cause in words. Reserve a solid danger button for the action that commits the destructive change. |
| Elevation and obscuring the background | `--shadow-menu`, `--shadow-pop`, `--scrim` | Menus and notifications use a close shadow. Dialogs have a broader shadow. A docked panel shares a single divider with the pane beside it. |

Choose the palette by the **visible scrim**. A confirmation, command panel or sheet that dims its surroundings uses the workspace palette throughout. Its header and body share the canvas, cards use the raised role, fields use the control role, and separators, focus, hover and selection follow their page equivalents. Full-screen mobile settings keep their grouped page surfaces.

A context menu, submenu, anchored preview, tooltip or notification floats over an undimmed parent. Apply `.popup-palette` to the popup content, including content rendered in a portal. Its panel uses the lighter floating surface. Its fields, borders, secondary text, highlighted rows and pressed states take their contrast from that surface. Keep the theme’s accent, focus ring and destructive colors meaningful in both palettes. A transparent layer that captures outside clicks still belongs to the undimmed case. Opening a menu inside Settings is a good check in each theme: the menu has its own palette while the rest of Settings keeps its page colors.

The current light canvas is warm gray-white (`#f6f5f2`) with a terracotta accent (`#a64a33`). Dark mode uses a neutral canvas (`#1c1c1c`) and a lighter accent (`#df947a`). Reference the roles in component styles so both themes change together. A media play button must remain visible over arbitrary pixels. Syntax, chart series, terminal ANSI colors and document paper have separate palettes because their colors carry content-specific meaning. [Theme tokens](../../src/styles/tokens.css) · [Shared controls](../../src/styles/components.css)

## Type, density and iconography

| Current default | Use and review |
| --- | --- |
| Montserrat with Sarasa Gothic SC | Interface labels and conversation prose. Compare Latin and Chinese ink weight, baselines, punctuation and bold spans in a real sentence. |
| Bitter with Noto Serif SC | Display type where the component calls for a display face. Use the shared interface heading roles for ordinary windows and pages. |
| Maple Mono NF CN | Commands, code and terminal cells. Preserve natural code spacing. Terminal grid measurements must survive switching between ASCII, CJK and emoji. |
| 14px base UI, 17px conversation type with 1.65 leading, 15px dialog and 17px page headings | These are source values. The build converts typography to rem, and mobile has a larger root size. At increased text size, verify that values, keycaps and action labels still fit. |
| 8px base radius, 36px regular button, 30px small button, 20px default icon | Size the hit area separately from the glyph. Dense desktop tools can use smaller glyphs. Mobile rows, grips and picker items need space for a finger. Mobile groups and content sheets have their own outer radii. |

Use the interface typeface for settings inputs and text areas on desktop and mobile, including URLs, paths, shell commands, environment variables, JSON parameters, and color values. A terminal preview uses the terminal typeface so it shows the configured result. Directory paths in the directory picker also use the interface face. Long paths can wrap in lists and remain editable in input fields. The Skill folders section puts Add in the heading and lists each path on its own row. A trailing Default label identifies the built-in directory. Only removable entries expose a delete action.

**Single-line text lists.** For a list scanned primarily by name or path, start with the `--text-list-*` roles: UI type at 15px (0.9375rem), line height 1.5, and a 48px minimum row height. Use the content, type hierarchy and neighboring controls to judge the final spacing. Optional secondary text uses 13px (0.8125rem) and expands the row as needed. Align the leading glyph and trailing control to the row center. The Skill catalog, its search results and its directory settings use this pattern. Place search and refresh on one toolbar. Card-based provider lists and multi-line context records have their own layouts. On account cards, service tags sit at the trailing edge on desktop and wrap beneath the account name on phones.

Shared geometry comes from `cfg.design`, applied to CSS variables at startup. Theme tokens and component styles supply the visual roles. Test a density change in both scripts, with a long value and the device text-size setting increased. [Design configuration](../../src/core/config.ts) · [Token application](../../src/ui/applyTokens.ts) · [Typography](../../src/styles/base.css) · [Build-time scaling](../../vite.config.ts)

Wish pictograms use a 24-unit grid, rounded caps and joins, and a typical stroke of 2 units. Objects combine a low-opacity wash of the current color with an outline. Arrows, crosses and checks use strokes. Cutouts should reveal the actual background. Files, folders and conversation bubbles share contours so related actions remain recognizable at small sizes. Provider brands use the separate brand component. An available delete action uses the ordinary bin. The slashed bin indicates disabled deletion. Explain linked services in the confirmation. [Icon vocabulary](../../src/ui/icons.ts) · [Provider marks](../../src/domain/providers/ProviderIcon.vue)

The paper crane and folded wordmark identify Wish. The launcher artwork includes a tile and safe space for platform masks. The in-app crane has a transparent background so it can sit on the current surface. Author these assets as SVG. Web builds render the manifest and Apple touch PNGs at their existing URLs. Native builds generate the platform variants. Keep review captures in local or CI artifacts so they can be replaced without adding binary files to source control. [Brand artwork](../../public/app-icons/) · [Wordmark](../../src/ui/components/Wordmark.vue) · [Web icon generation](../../tools/app-icons.ts)

## Page geometry, scrolling and mobile

The desktop shell starts at 900px. The left session list defaults to 256px, resizable from 200 to 520px. Its default row is 36px high, the top bar is 56px and the reading column caps at 46rem. The right sidebar also measures the **remaining workspace**. Below 800px available it becomes a drawer. Docking reserves at least 480px for chat. To review this behavior, hold the browser width constant and resize or collapse the left pane. A single screen-width breakpoint cannot exercise that case. [Layout configuration](../../src/core/config.ts) · [Sidebar sizing](../../src/ui/components/IslandSidebar.vue)

Give each mobile view one clear return path. A short confirmation remains centered. A long, browsable detail can use an expandable bottom sheet or a secondary page. A file preview puts Back, filename and essential actions in one header. Search and filter controls can wrap or move to a secondary page. Back dismisses the innermost menu, sheet or page first. Nested selection and scrolling must work before the surrounding sheet interprets a drag as dismissal. [Dialog and Back behavior](interactions-and-ui.md) · [Source preview](../../src/domain/media/SourcePreview.vue)

The document is fixed to the visual viewport. Give each vertical content area a scroll owner and allow shrinking flex or grid children with `min-height: 0` and `min-width: 0`. Keep a dialog's header and footer outside its scrolling body. Verify that its last field and action can be reached with the software keyboard open. When the keyboard closes, restore usable height without moving the transcript. Floating controls account for safe areas and the visible viewport. [Viewport handling](../../src/ui/viewport.ts) · [Shell layout](../../src/styles/layout.css) · [Modal](../../src/ui/components/Modal.vue)

The notification preview opens in the current device mode. Its Desktop and Mobile controls replay the same event in the bottom corner or as a top banner. Both placements use the live stack and respect safe-area insets.

Notification tone travels with the event into the live card and its preview. Use the error color for a failed operation, warning for an automatic retry or stream recovery, success for completed work, and neutral ink for general information. Carry the tone through the icon tile and a light surface tint. Give all four edges the same fine border. Keep the message legible in ordinary foreground text. A distinct icon and a verb explain the event even when color is unavailable.

## Controls, labels and lists

- Use `--fg-placeholder` for empty fields, including search, select and composer prompts. Keep field labels visible after typing, and render entered values in the ordinary foreground. Put credential syntax, saved-value behavior and long lifecycle notes behind a labeled information button beside the field.
- **Choose an action's weight from its consequence.** The filled primary button completes the current task. Ghost buttons fit secondary tools, edit actions and close controls. A danger-colored icon identifies deletion in a row. The solid danger treatment belongs on the final confirmation. Describe the consequence with the object name, such as deleting an account together with its linked image service. [Button variants](../../src/styles/components.css) · [Account removal flow](../../src/features/settings/AccountSettings.vue)
- **Make the selected value visible at rest.** The shared select supports a compact capsule when explicitly requested for two or three options. A long searchable list keeps the search field, selected-item mark and empty result in predictable locations. Some mobile selectors open a secondary page. Keep help and loading notes outside fixed-height virtual rows so scrolling and keyboard selection continue to agree. [Select field](../../src/ui/components/SelectField.vue) · [Provider picker](../../src/domain/providers/PickerList.vue)
- **Keep filter names stable.** In the Library, *Filter → Show hidden files* includes hidden items alongside visible ones of the chosen type. The check mark indicates the current setting. Keep this choice in the filter menu and reserve Back for navigating to a previous location.
- **Give the row one identity.** Keep the icon and actions stable as names grow. Let the title and secondary text shrink or wrap according to their role. A quick-switch row can truncate its path after the name. A source preview needs a way to read the full contents. The Context tab keeps generation selection and filtering above a virtualized list of short previews. Open an entry to read the full text, compare tool outputs or inspect its JSON. Verify labels, names and shortcuts in both locales. [Quick switch](../../src/features/shell/SessionQuickSwitch.vue) · [Settings card](../../src/features/settings/SettingsItemCard.vue)
- **Keep essential choices in the open.** A switch label should explain what enabling it does. Use a hint for details such as scope, prerequisites or side effects. For multi-step or asynchronous actions, show the current step, result or reason to retry. In a retry detail, let the reader control expansion while the request state updates. [Settings help](../../src/domain/settings/SettingHint.vue) · [Retry status](../../src/features/sessions/RetryStatus.vue)

## Settings, accounts and data views

Desktop settings use the existing right pane for editors, catalogs and browsing. Extension tools open with a category list on both layouts. Use the same label and action-button layout as Key bindings on desktop and full-width navigation rows on phones. For settings rows that open a subpage or preview, place the identifying icon before the row title. Put the action text and navigation arrow together in the trailing button. Separate adjacent cards for peer destinations by 10px. Skill and linked-file lists use open rows with rounded hover and focus fills. Align icons, titles and trailing controls across rows. Use spacing as the row separator and keep the full row height interactive. Each category has its own page for delivery mode and providers. Spell out delivery choices in a Wish select on desktop and mobile. Place usage and provider-order notes behind information buttons beside their respective controls. A nested page has a Back action, keeps the category rail available, and returns to its parent with the settings draft intact. Provider and model creation use dialogs for preset selection and initial configuration. Short confirmations such as deletion and discarding changes also use a modal. Skill folder management and preset environment variables open from their own settings rows. Browse skills, Open keymap and Browser shortcuts enter subpages in the same detail pane. The shared header shows the destination title and a Back action. Folder navigation and skill details follow the same hierarchy on desktop and mobile.

On desktop, the settings sidebar owns category selection and search. The content pane owns the current object. Align labels and controls across related rows. Keep short explanations beside their field and move longer help into the shared hint. Add copy where a label needs context or an action has consequences. On mobile, group related fields and give complex editors their own page. Ordered services support both drag and keyboard movement. [Settings layout](../../src/domain/settings/settings.css) · [Settings window](../../src/features/settings/SettingsView.vue) · [Select field](../../src/ui/components/SelectField.vue)

Account, model-provider and image-generation lists use a single-line identity with a brand mark and a name. Model and image-service rows retain their enabled state, and ordered image services show their position. Omit the subtitle when it would repeat internal IDs, linked-service names, plan details or a model/account pair. Account cards show distinct linked service categories as quiet tags before the trailing actions. Editors and removal confirmations can present individual service identifiers where it informs a decision. Two accounts can share a brand and display name. Derive their linked services and removal impact from configuration. In setup, introduce platform, credentials and model choices in sequence. Desktop can focus the first field in a new step. Mobile focuses the step heading to avoid opening the keyboard over the introduction. The connection screen offers existing accounts, an add action and a way to reach device preferences before signing in. [Account settings](../../src/features/settings/AccountSettings.vue) · [Onboarding](../../src/features/onboarding/ProviderSetup.vue) · [Connection screen](../../src/features/connection/ConnectView.vue)

Model legends show the two highest-usage rows at the current card width and disclose the remaining models in descending Token usage. Folding a legend preserves every series and total.

For statistics and account readings, keep the value, unit, time range and legend readable together. Pair series colors with names and use the theme's series and heat scales. Distinguish zero, no observations, unlimited quota and failed reads. A quota bar, its caption and its accessible value should all express the same direction, currently *remaining*. When refreshing existing data, keep the previous reading and show its timestamp. Debug settings pair each preview title with an explicit action, matching the keymap entry. The style gallery groups sample buttons by subject and mounts the selected example in a compact dialog. The first-run walkthrough opens above settings and uses local preview input through all three steps. ## Feedback, input and motion

| Situation | Current presentation | Cases worth exercising |
| --- | --- | --- |
| Available, busy or disabled action | Align label, glyph and actual availability. Guard repeated submission while work is pending. Distinguish focus, hover and selected value. | A focused icon button, an unavailable action with a reason, a keyboard user inside a nested menu. |
| Initial load, refresh, empty result or failure | Local loading feedback occupies the relevant area. An empty state says what is empty or provides the next action. A failure gives a useful cause and a recovery action when available. | Slow response, refreshed data already on screen, long error details and recycled rows. |
| Transient result or update offer | Stack rectangular notification cards at the lower right on desktop and at the top safe area on mobile with a close shadow and a dismiss control. The stack is capped at 360px on desktop and 440px on mobile. Up to three transient cards show at once. They time out after 3.6 seconds and pause while hovered or focused. An update offer persists until handled. | A settings dialog open, a visible software keyboard, several arrivals, keyboard activation and reduced motion. |
| Session activity | Identify the session and offer to open it. Report each scheduled upstream retry and each stream recovery attempt once. Include the attempt number and the failure reason when available. A failed run carries its cause. Initial idle readings, repeated idle updates and the first reading after reconnect stay quiet. Hidden pages can use system notifications when enabled and permitted. Routine compaction progress and results stay in the conversation. | Two sessions interleave, one run fails, a question arrives, a compaction runs on its own, or the connection drops. |
| Destructive change | The confirmation identifies the object and scope. Its action says what will happen. A transient notification can report the outcome. | Cancel and return to the same selection or draft. For an account, check its linked and unlinked cases. |

At the bottom of the transcript, name the reported activity and add a short detail when available (for example, a search query or the host being read). Use extension capabilities to identify provider-specific tools. Keep the glyph in a fixed slot as the activity changes. SVG motion should describe the action, such as a moving scan line for reading or a waveform for audio. Reduced-motion mode keeps the glyph still. Tool output and token deltas stay outside the status announcement.

Conversation work indicators use the shared Wish icons, with the same foreground as the status text. Animate a meaningful feature of the glyph and keep a readable still frame for reduced motion. Waiting for a model response uses the shared circular spinner at the same size and color as its neighboring status icons. The ring stays still when reduced motion is enabled. A retry card supplies its own warning foreground.

Give icon-only buttons accessible names. Expose expanded, selected and busy states where they apply. Route keys through the focused editor or control, then its region, then application shortcuts. Exercise IME input, text selection, a terminal and an open menu. Touch actions must be reachable without hover. Use motion to explain entry, exit or movement and honor reduced-motion preferences. If an exit animation stalls, release its scrim, scroll lock and focus ownership. ## Why these defaults evolved

The local commit IDs below can be inspected with `git show <id>`. Where the same surface changed several times, compare the later implementation with the earlier one before reviving its styling.

| Topic | Changes in the repository | What to look for on the next revision |
| --- | --- | --- |
| Focus and dividers | September's `9433b04` consolidated form focus. November's `cc8827a` used existing control borders and drew a single sidebar divider. | Inspect a focused control in its row and the edge where two panes meet. Double borders exaggerate both. |
| Sidebars | `6babfcc` introduced an island sidebar. `2f0412d` moved to a flush divided panel. `85d67b9` brought terminal tabs into the sidebar's segmented-control style. | The name `IslandSidebar` survives the original design. Choose the surface for its docked or floating state. |
| Multilingual type | `74b5c11` balanced mixed scripts. `574eff1` calibrated weights during font generation. `e1736cb` and `89ee795` corrected Markdown emphasis beside CJK punctuation and strengthened bold text. | Compare actual sentences including numbers, inline code, punctuation and bold text at device text sizes. |
| Composer surfaces | `34ebdb1` introduced a translucent composer, then `307da95` adjusted its opacity. `6bed752` and `fbafb74` refined expanded attachments and fixed styles across the portal boundary. | Place dense transcript content behind the composer and open the real attachment popover. Check contrast and how much history is covered. |
| Mobile detail and gestures | `59a11dd` assigned modal lists one scroll owner. `e6e3f2f` distinguished short confirmations from content sheets. `09c87bc` and `afc99c2` refined expansion and the preview header. | With one hand, open a detail, select text, scroll to its end, expand and return. Watch for unintended sheet dismissal. |
| Icons, covers and selection | `f4f4d93` made unselected document covers neutral. `be410a1` designed folder covers for thumbnail sizes. `10f3211` and `81db474` refined outlines, washes and cutouts. | Compare resting, hovered and selected items at displayed size against both backgrounds. |
| Pickers and commands | `e2b32ee` kept explanatory notices outside fixed-height virtual rows. `d6f8194` simplified the completion highlight. `db75012` introduced compact physical keycaps. | In a short row, distinguish the active candidate, its matched text, its explanation and the key that invokes it. |
| Recent feedback changes | The 20 November worktree unified update and result notifications, removed routine compaction popups and corrected the slashed bin on removable accounts. | Check the actual availability of the operation and whether the event deserves the user's attention. |

## Reviewing the next change

1. **Describe a concrete difficulty.** Record the surface, input method and action. “On a phone, a long filename pushes Back out of the header” gives a reviewer something to reproduce.
2. **Start with real components.** The debug style preview renders local examples of attachments, tool results, code highlighting and loading states. Its 390px narrow column is useful for wrapping. Use a narrow viewport or device to check the sheet, keyboard, safe areas and Back gesture. [Style preview](../../src/features/debug/StylePreview.vue)
3. **Test the states the change touches.** For a delete button, compare enabled, disabled, linked services, cancellation and confirmation in both themes. For a transcript change, add long bilingual content, streaming, scroll anchoring and the software keyboard. Exercise keyboard and pointer paths when the component exposes both.
4. **Revise the relevant section with the implementation.** Record which default or behavior changed, the scenario that improved and where to verify it. A proposal can remain open while alternatives are tried. Keep screenshots with the review artifacts and put reproducible scenarios and source links in the guide. [Developer checks](README.md)
