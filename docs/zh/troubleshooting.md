# 故障排查

[文档目录](README.md) · [English](../en/troubleshooting.md)

先用三条命令分清问题出在哪一层：

```sh
curl -s http://127.0.0.1:8790/healthz       # serve.ts 在运行：{"ok":true}
curl -s http://127.0.0.1:9780/health        # Wish 服务端在运行
./pnpmw selftest:api http://127.0.0.1:8790  # 整条链路，只读检查
```

在浏览器中打开 `/#/selftest?auto=1`（或设置 →“界面”→“连接诊断”），可以从页面端做同类检查。

## 连接

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| `421 {"error":"rejected","detail":"unexpected host"}` | 浏览器中使用的地址不在允许的主机名之列。 | 按浏览器里的写法把它加入 `ALLOWED_HOSTS`：带端口（`192.168.1.20:8790`），或者在 443 端口的 HTTPS 后面不带端口（`wish.example.com`）。然后重启 `serve.ts`。 |
| 发送消息或保存设置时返回 `403`，提示 `cross-origin mutation` 或 `cross-site mutation` | `Origin` 请求头与 `Host` 不一致。通常是反向代理改写了 `Host`，否则就是请求来自其他网站。 | 让反向代理原样转发 `Host` 和 `Origin`（nginx：`proxy_set_header Host $http_host;`）。见[部署](deployment.md#通过反向代理启用-https)。 |
| 启动时显示“无法读取服务配置” | 第一个请求 `GET /api/config` 失败，具体原因显示在下方。 | 按下面几行排除原因后点击“重试”。 |
| `401`，或提示“未通过身份验证，请检查访问令牌。” | Wish 服务端要求令牌，而 `serve.ts` 没有配置令牌或令牌不对。 | 把 `WISH_HTTP_TOKEN` 设为服务端 `bearer_token_env` 所指环境变量的值，然后重启 `serve.ts`。 |
| `502 {"error":"upstream_unreachable"}` | `serve.ts` 连不上 Wish 服务端。 | 启动 Wish 服务端，并检查 `WISH_UPSTREAM`。 |
| 顶部出现“离线模式: API 不可用” | 与 `/api/events` 的实时连接断开了，应用会自动重连。 | 检查 Wish 服务端和反向代理。反向代理不能缓冲事件流（nginx：`proxy_buffering off;`）。 |
| 登录页提示“无法连接到这个地址” | 地址有误、服务器没有运行，或者它没有设置访问令牌，因而拒绝其他网页的连接。 | 检查地址和服务器是否运行；对方服务器需要设置 `bearer_token_env`。见[部署](deployment.md#直接连接其他服务器)。 |
| 登录页提示“此页面通过 HTTPS 打开……” | HTTPS 页面无法连接普通 HTTP 地址。 | 通过 HTTPS 发布对方服务器。 |
| 登录页提示“这个服务器需要访问令牌”或“访问令牌不正确” | 没有填写令牌，或与服务器 `bearer_token_env` 的值不一致。 | 填写正确的令牌。 |
| 连接其他服务器后一直停在“无法读取服务配置” | 那台服务器已无法访问，或它的令牌变了。 | 点击“重试”旁边的退出按钮，重新连接。 |
| `serve.ts` 启动时报 `ENOENT … dist/index.html` 并退出 | `serve.ts` 旁边没有构建产物。 | 运行 `./pnpmw build`，并把 `dist/` 放到 `serve.ts` 旁边。 |
| `serve.ts` 报 `unsupported /api protocol` 并退出 | `WISH_UPSTREAM` 不是 `http://` 或 `https://` 地址。 | 修正这个变量。 |

## 在局域网中用普通 HTTP 访问

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 无法安装应用；从不出现“新版本已就绪”；自检显示 Service Worker 不受支持 | Service Worker 和应用安装都要求安全上下文。 | 通过 HTTPS 提供服务（见[部署](deployment.md#通过反向代理启用-https)），或在服务器本机用 `http://localhost` 访问。 |
| 提示“无法开启通知” | 浏览器不支持通知、通知权限被拒绝，或页面不是安全上下文。 | 在浏览器中允许该网站发送通知，并使用 HTTPS。 |
| “运行时保持屏幕唤醒”不起作用 | 浏览器不支持 Wake Lock，或页面不是安全上下文。 | 使用 HTTPS 和支持该功能的浏览器。 |

## 会话

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 删除、编辑标签、“立即压缩”或“清空上下文”时提示“会话正在运行，请等本轮运行结束后再试。”；保存会话的压缩设置时提示“会话运行时只能修改模型、思考强度和输出上限……”（均为 `409`） | 这些操作需要会话处于空闲状态。 | 等本轮运行结束或点击“停止”后再试。重命名、模型、推理强度、会话的 Shell 和队列在运行中都可以修改。 |
| “会话已被其他操作修改。点击重试读取最新设置后再选择。” | 打开选择器后，会话又被修改过。 | 点击“重试”，然后重新选择。 |
| “队列已变化，排序未保存。”或“消息刚被运行中的回复处理,未能取回” | 运行已经先一步取走了这条消息。 | 无需处理，消息已经送达。 |
| “无法定位到该消息（超出回填范围），请缩小搜索范围后重试” | 这条搜索结果离已加载的历史太远，无法定位。 | 缩小搜索范围后再试。 |
| 服务端意外停止后，某个会话显示 `ToolOutcomeUnknown` | 服务端在工具调用过程中被强行终止，它不会自行重复工具调用。 | 先确认那条命令实际做了什么，再发送消息继续。 |

## 设置与提供商

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 保存时提示“配置已在其他地方修改，请重新载入后再保存。” | 配置在别处被保存过。Wish 通常会自动合并你的修改并重新保存，只有重试也失败时才会看到这个提示。 | 点击“放弃修改”，然后重新修改一次。 |
| “无法删除提供商” | 默认模型属于这个提供商。 | 先在“服务与会话”中换一个“默认模型”。 |
| “服务器上没有环境变量 NAME。” | 某处 `${NAME}` 引用的变量在 Wish 服务端进程中不存在。 | 在服务端的环境中设置这个变量并重启服务端，或者直接填写它的值。 |
| 出现红色的“运行失败”，或琥珀色的“自动重试中”“上游已暂停” | 提供商拒绝了请求或请求失败。琥珀色提示表示服务端正在自动重试。 | 检查“服务地址”“请求路径”“协议”和凭据，以及“网络代理”和“使用代理”。 |
| “无法读取模型目录” | 提供商刚添加还没保存、没有配置模型目录，或读取目录失败。 | 先保存。没有目录时，已配置的模型照样能用，也可以通过“自定义”手动添加模型 ID。 |
| 模型收到的是一段关于文件的说明，而不是图片 | 这个模型没有标记为支持图片输入。 | 如果模型确实支持，在它的模型设置中打开“支持图片输入”。 |
| ChatGPT 登录时，`localhost` 页面打不开 | 浏览器不在服务器那台机器上。 | 复制地址栏中的完整链接，粘贴到“粘贴 localhost 授权链接”，再点击“完成登录”。 |
| “Codex 登录回调端口 1455 和 1457 都已被占用。” | 服务器上有其他程序占用了这两个端口。 | 释放其中一个端口，然后重新登录。 |

## 部署之后

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 界面还是旧版本 | 页面仍在运行上一个版本。 | 出现提示时点击“立即更新”；没有 HTTPS 时直接刷新页面。会话信息中的“构建”显示当前运行的提交。 |
| 部署前就开着的页面，打开某个页面时失败 | 旧版本请求了新构建中已经不存在的文件。 | 刷新页面。 |
| 不确定问题出在客户端还是服务端 | | 对比 `/#/selftest?auto=1` 和 `./pnpmw selftest:api <地址>` 的结果；两者都失败时，问题在服务端或反向代理。 |

## 本地数据

| 现象 | 解决办法 |
| --- | --- |
| 本地状态异常：列表宽度不对，缓存的统计或模型目录过时 | 设置 →“界面”→“清除本地数据”，然后刷新页面。服务端的会话和设置不受影响。 |
| 想清除所有本地内容，包括模型颜色和应用缓存的文件 | 在浏览器设置中清除该网站的数据。 |
